## What it does

Projects are the work shown in the *Selected work* part of your portfolio. Each published project also gets its own page at `/projects/its-address`.

## Adding a project

1. Fill in **Add a project**: the name, category, description, details, technologies and features (one per line).
2. Add the **GitHub repository URL** and **live demo URL** if there are any.
3. Tick **Source repository is publicly accessible** only if anyone can open it without signing in. Otherwise visitors see "Private source code".
4. Tick the demo check only after confirming the demo opens publicly without a login.
5. Choose a **featured / sharing image** from the media library.
6. Save. Drafts stay private until you publish them.

## Authorship and licences

The project form asks who wrote the work, who maintains it, the licence, and any contributor notices. Only state authorship you have checked: owning a GitHub account doesn't by itself prove you wrote everything in a repository.

## Good to know

- The **stable URL slug** is created once from the name. Renaming a project doesn't change its address, so old links keep working.
- **Display order** sets the order on the site, lower numbers first.
- The optional SEO title and description override the defaults for that project's page.
- Every save keeps the previous version in [Content history](/admin/revisions).
- To add a project to the header menu, see [Menus](/admin/help/menus).
